Show what Meta SAM 3.1 actually saw: an aerial photo basemap with SAM's segmentation (buildings, tree canopy, car parks, construction sites) drawn over it for the 10 featured stations, revealed class by class, so users and judges can see the model at work, not just percentages.

Context: read `AGENTS.md`. SAM batch and its tile cache: `scripts/sam/batch.ts`, `scripts/sam/concepts.ts`; mask-to-polygon code and the corrected pixel-to-ground conversion: `scripts/sam/sites.ts` and `scripts/sam/polygons.ts` (the conversion uses RES / cos(latitude) Web Mercator units per pixel, as `fetchChip` in `batch.ts` fetches the chips; keep that exact maths). Loader pattern and MultiPolygon storage: `src/server/db/real-sites.ts`, `db/schema.sql` (`sam_sites`). Map: `src/components/portal/MapView.tsx`, `LayerPanel.tsx`, `MapGuide.tsx`, `LandUsePanel.tsx`; Meta models list `ModelsPanel.tsx`.

Build:
1. Shared georeferencing: move the chip-pixel to lon/lat conversion out of `sites.ts` into `scripts/sam/polygons.ts` (one function used by both scripts), with a unit test that a pixel at a chip's edge lands 256 m (at 0.5 m per pixel, 512 px) from the chip centre on the ground.
2. `scripts/sam/cover-polygons.ts` (npm `sam:polygons`): from the cache only (no SAM calls), every class's masks for each featured station → merged polygons → outline traced and simplified (start at 1.5 m tolerance; drop parts under 20 m²) → `data/derived/sam_cover_polygons.geojson` with station_id, class and area_m2. Print the count per class per station and the file size; aim for under 3 MB of GeoJSON per station (raise the tolerance or minimum area if needed and say so). Never commit `data/`.
3. Schema + loader: table `sam_cover_polygons (id, dataset_id, station_id, class, area_m2, geom MultiPolygon 4326)` and view `v_sam_cover_polygons` granted to `agent_ro`; loader `src/server/db/real-cover-polygons.ts` (store with `st_multi(st_collectionextract(st_makevalid(...), 3))`), wired into the local DB build and `db:setup` (`--load-sam-polygons`, part of `--load-real`). Loader test.
4. `GET /api/v1/layers/sam?station=`: the station's polygons as GeoJSON, plus per-class counts and the capture date. Cache-Control for a day.
5. Map:
   - "Aerial photo (NSW)" basemap toggle: raster tiles from the NSW Spatial Services imagery tile service (`https://maps.six.nsw.gov.au/arcgis/rest/services/public/NSW_Imagery/MapServer/tile/{z}/{y}/{x}`), with the attribution "Imagery © Spatial Services NSW (CC BY 4.0)". Check the tile URL works before relying on it; if it does not, fall back to the MapServer `export` endpoint the batch uses.
   - "What SAM 3.1 sees" layer with the Meta dot: building red, tree canopy green, car park blue, construction site amber, about 45% fill with a thin outline; legend with per-class counts ("8,206 buildings, 3,112 tree crowns…"); an opacity slider; and "Hold to see the photo alone" (press and hold hides the masks).
   - Reveal: when the layer is turned on, fly to the station (close view), switch the basemap to the aerial photo, then fade in the classes one after another (about 0.6 s each) with a caption "Meta SAM 3.1 is segmenting NSW aerial imagery: buildings… tree canopy… car parks… construction sites". Skip the animation under `prefers-reduced-motion`.
   - For stations without SAM data, the toggle is disabled with a tooltip naming the featured stations.
6. Entry points: a "Show what SAM 3.1 saw" button in the land-use panel's aerial cover section and next to SAM 3.1 in the Meta models panel; both turn on the reveal for the selected (or first featured) station. When the agent answers a land-use or aerial-cover question about a featured station, include a `show_layer` action with `layer: 'land_use'` and `classes: ['sam']` (`MapAction` itself must not change), and have the map treat that as "turn on What SAM 3.1 sees".
7. Explain it in `MapGuide.tsx`: one capture date, what each colour means, that masks can overlap and miss shaded canopy, and that the same pipeline runs on any city's imagery or Dronovation drone surveys.
