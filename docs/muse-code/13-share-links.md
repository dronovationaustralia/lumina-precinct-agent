Add shareable links to Lumina Precinct Agent: anyone can share a precinct card or a verified answer as a public link, and when it is posted on X, LinkedIn or Slack the preview shows a rich image (the Muse Image illustration with the headline figures).

Constraints that shape the design: the deployed app has read-only database access (`DATABASE_URL_RO`), so there is nowhere to store shared answers; and nobody must be able to forge figures in a shared link. So links are **stateless and signed**: the content travels in the URL, compressed, with an HMAC signature using `AUTH_SECRET`.

Context: read `AGENTS.md` and the Next.js 16 docs in `node_modules/next/dist/docs/` on metadata, `generateMetadata`, Open Graph images and `ImageResponse` from `next/og` (APIs may differ from older versions). Auth: `src/proxy.ts` (its matcher decides what needs sign-in) and `src/server/auth/session.ts`. Precinct card data: `src/server/briefing.ts` and `src/app/api/v1/briefing/[station]/route.ts`. Answer cards: `src/components/portal/AnswerCard.tsx` and `exporting.ts`.

Build:
1. Precinct links `/p/[station]`: a public page (no sign-in) showing the station name, lines, the Muse Image illustration (from the briefing cache; generate if missing, rate limited) and the verified figures with sources and dates, plus a "Explore in Lumina" button to the sign-in page. `generateMetadata` gives title and description; an Open Graph image route renders 1200×630: the illustration on one side, the station name and three headline figures on the other, the Lumina mark, and "Illustration: AI-generated (Muse Image) · Figures: NSW open data, checked". Cache the OG image per station (in memory and temp file) like the briefing.
2. Answer links `/a/[token]`: `token` = base64url(deflate(JSON of question, station, templates, facts, sources, verification status, model, created_at)) + "." + HMAC-SHA256 signature. `src/server/share.ts` signs and verifies; reject tokens over 6 KB (drop the chart and tool call details first) and any token whose signature fails. The public page renders the answer like the answer card (figures as tiles with source and date, "How this answer was made" summary), never re-running the agent. The OG image shows the question and up to three figures.
3. UI: a "Share" button in the answer actions and on the Brief me card: it creates the link (`POST /api/v1/share` signs on the server for signed-in users), copies it, and shows a toast; on mobile use the Web Share API when available.
4. Proxy: let `/p/`, `/a/` and their OG image routes through without sign-in; keep every `/api/v1` route protected except what the public pages need (prefer rendering on the server so no new public API is needed). Rate limit the public pages.
5. Tests: sign/verify round trip, tampered token rejected, size limit, public routes reachable without a session and other routes still protected.

Run `npm test`, `npm run typecheck`, `npm run lint`. CHANGELOG (Sydney date): "Share links: public precinct cards and verified answers with rich previews (built with Muse Code)."
