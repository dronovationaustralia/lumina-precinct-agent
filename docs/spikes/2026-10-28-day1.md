## 1. How the Meta Model API is called

- **OpenAI-compatible.** Base URL `https://api.meta.ai/v1`, `Authorization: Bearer <key>`.
  Supports Responses, Chat Completions, and an Anthropic-style Messages API.
- **Key env var:** `MODEL_API_KEY`. The OpenAI SDK does not read it automatically, so pass
  it as `apiKey` (our code does this everywhere).
- **JS SDK:** `openai` (we have v7). LangChain.js: `@langchain/openai` `ChatOpenAI` with
  `configuration: { baseURL }`.

## 2. Spike 1: Muse Spark tool calling through LangChain.js

`spikes/01-muse-spark-tools.ts` runs three demo questions on both Chat Completions and
Responses with two tools (`query_metric`, `search_place`). Tool results are labelled
fixtures, not real data. It records the tools chosen, Zod validation of the arguments,
stray digits outside `{fN}` placeholders, latency and tokens.

Documented constraints that shape the agent graph:

- **`tool_choice` supports only `"auto"`.** `"none"`, `"required"` and named tools return
  HTTP 400. So LangChain's `withStructuredOutput()` in function-calling mode (which forces
  a named tool) will fail. For the compose step use JSON-schema structured output, or a
  plain JSON answer validated by Zod. Check this on day 3.
- **`strict` defaults to false**, and generated arguments "are not guaranteed to validate".
  We validate every tool call with Zod (the harness already does).
- `parallel_tool_calls` defaults to true; the 5-call budget must count each call.
- Tool names must match `^[a-zA-Z0-9_.-]+$` with at most one dot.

Dry-run findings (mock server, which logs the exact payloads LangChain sends):

- LangChain sends no `tool_choice`, no `strict` and no `parallel_tool_calls`, so the
  defaults apply. Good.
- Tool JSON schemas from Zod 4 include `"$schema": ".../draft/2020-12/schema"` and
  `additionalProperties: false`. **Check live** that Meta accepts the `$schema` key.
- In Responses mode, LangChain replays the `function_call` and `function_call_output`
  items each turn (stateless) and sends `text: {}`. Meta's docs show
  `previous_response_id` instead. **Check live** that the stateless replay is accepted.
  Until then, **Chat Completions is the default** for the agent.
- With Responses, `AIMessage.content` is an array of blocks; use `message.text`.
- The verifier needs an allowlist for ring labels ("800 m", "2 to 5 km") so they are not
  counted as unverified numbers.

## 3. Spike 2: SAM 3.1 on two NSW chips

`spikes/fetch-nsw-chips.ts` exports 1024 × 1024 px JPEGs at about 0.25 m from the
NSW_Imagery MapServer, centred on Parramatta and Chatswood (approximate coordinates;
GTFS `stops.txt` replaces them on day 2). `spikes/02-sam-landuse.ts` sends four prompts per
chip and writes cover % and an SVG overlay per chip.

How SAM 3.1 is called (from Meta's cookbook):

- `POST /v1/responses`, `model: "sam-3.1"`, `stream: true`. Input is one user message with
  an `input_text` noun phrase and an `input_image` data URL.
- **One noun phrase per request.** Four classes means four requests per chip.
- Output is a text grammar (`<0f>id<|box;...|><|mask;...|>`, frame 0 even for images),
  decoded with Meta's `@meta-sam/parser` (`parseImageStream`, `decodeMaskToRaster`,
  `decodeMaskToSVGPath`). Each mask raster covers its record's `bounds` box; the raster
  can be smaller than the box, so we scale when painting it into the chip.
- The API sends `response.content_part.done` but not always `response.output_text.done`,
  which the parser needs; the spike synthesises it (the same workaround as the cookbook).
- Classes can overlap (canopy over a car park), so cover is per class, not a partition.

Dry run: the full path (stream, parse, decode, union bitmap, cover %, SVG) works on the
parser's reference masks.

**Batch sizing to confirm with live latency and cost.** The full design (0.25 m inside
800 m, 0.5 m out to 2 km) needs about 49 inner chips plus about 48 outer chips per station,
so roughly 100 chips × 4 classes ≈ 400 requests per station, or about 4,000 for 10
stations. If that's too slow or too costly against the $150 credit, options are 0.5 m
everywhere (about 25 chips per station inside 2 km), larger chips if SAM accepts them,
or 800 m only at 0.25 m. Decide on day 4.

Licence and capture dates for the NSW imagery are **not confirmed**. Chips are gitignored
until they are.

## 4. Spike 3: Muse Voice Transcribe

`spikes/03-voice-transcribe.ts` uploads `spikes/audio/question.wav` twice, without and with
keyword biasing for the 10 station names, and scores word error rate against the expected
sentence.

How it is called (from Meta's cookbook):

- `POST https://api.meta.ai/v1/asr/transcribe`, Bearer auth, **multipart** with two parts:
  `request` (a JSON part: `model`, `mode`, `audioEncoding: "WAV"`, optional `keywords`,
  `languageBias`) and `audio` (the file).
- Modes: `PUSH_TO_TALK` (default), `ENDPOINTING`, `DIARIZATION`.
- Limits: 32 MB body, 10 minutes of audio. Recommended input: mono 24 kHz 16-bit WAV
  (`ffmpeg -i in.m4a -ac 1 -ar 24000 -sample_fmt s16 out.wav`).
- Response: `{ sessionId, transcript, audioDurationMs, turns[] }`.
- Realtime alternative: `wss://api.meta.ai/v1/asr/realtime` (PCM 16 or 24 kHz). Hold-to-talk
  in the portal can use the one-shot POST; use realtime only if latency demands it.

Dry run: multipart shape accepted by the mock; WER scoring works.
